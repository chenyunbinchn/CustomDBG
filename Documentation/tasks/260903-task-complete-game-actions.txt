1. 先固化的实现原则
------------------------------------------------------------------------

1.1 Context 与 Action 载荷分工

  - BattleActionContext 只提供本次执行可访问的世界状态和服务，例如 BattleState、
    RandomManager、GameActionManager/BattleRuleSystem。
  - Action 自己携带业务事实：SourceActorId、TargetActorId、可选 SourceCardId、
    TargetCardIds、Value。
  - 禁止用 context.PlayerState 猜测通用 Effect 的目标。context.PlayerState 只可作为
    命令发起者的便捷引用，并最终应能由 Player Id 校验得到。

1.2 Id 与目标

  - 实体使用 ActionEntityId；卡牌使用 CardInstanceId。
  - 禁止把手牌下标写进 Command 或 Action。
  - 战斗实体目标与卡牌目标分开建模；不要继续用同一个 EnumTargetType 同时表达
    SelectedEnemy 和 SelectedHandCard。
  - TargetResolver 是目标合法性和展开的唯一入口；不支持的组合在数据加载期失败，
    禁止 fallback 到 picked。

1.3 状态修改与失败语义

  - 每一次原子状态修改都由 Action 执行。
  - “命令出队时目标就非法”必须拒绝命令；“命令合法但前序 Action 已使目标死亡”可以
    返回明确的 Fizzled/TargetGone 结果，不能只打一条模糊日志。
  - 配置错误在加载期失败；运行时战斗状态损坏进入 BattleFaulted，停止接受普通命令，
    不允许继续产生不同步状态。

1.4 建议的基础规则

  - Value 为数量/伤害/格挡/能量获得时必须 >= 0；减少类语义使用独立 Action。
  - Hp 最低为 0；Block 最低为 0。
  - 手牌上限默认 10。抽牌遇到满手时停止，本次未抽的牌继续留在抽牌堆；先写入规范再
    实施，如项目决定其他规则只改规范与测试，不在 Action 内散落特例。
  - GainEnergy 不受“每回合恢复值”上限截断；PlayerInfo.EnergiesLimit 作为回合开始恢复
    值，不当作硬容量。若设计另有决定，先更新规范。
  - 选择超时由主机产生并广播一个确定的 ChoiceCommand 结果；客户端不得按各自墙钟
    独立自动选择。

实施前将最终规则写入：
  Documentation/documentations/260903-game-action-execution-standard.txt

2. 工作包 A：P0 执行安全与数据验证
------------------------------------------------------------------------

[ ] A-01 为 CardDefinitionManager 增加 EffectValidator：
         - EffectType 不得为 None；
         - CostEnergy 不允许作为作者配置 Effect；
         - Value/StatusType/TargetType 组合必须被对应 Action 支持；
         - 不支持的多目标、卡牌目标在实现前直接拒绝加载。

[ ] A-02 GameActionManager.Add 拒绝 null；Release 构建也必须执行该校验，不能依赖
         Conditional MyAssert。

[ ] A-03 加固 ActionExecutor：
         - 增加 CurrentAction；
         - try/finally 保证 IsRunning 必定复位；
         - 成功、Canceled、Faulted 终态由状态机明确控制，不无条件覆盖；
         - 异常时记录 ActionId/类型/命令 Id，标记 BattleFaulted，停止普通 Pump；
         - 定义清空剩余批次还是保留故障快照，推荐保留快照供诊断、退出战斗时统一清理。

[ ] A-04 给单条命令增加确定性的 MaxExpandedActions 上限，阻断 Hook 反应死循环。计数
         属于命令结算链，不使用帧数或墙钟。

[ ] A-05 定义 EnterBattle/ExitBattle/故障退出的清理：ActionQueue、Pending commands、
         CurrentAction、IsRunning、ActionId、选择请求和 BattleFaulted 不得跨战斗残留。

[ ] A-06 为 PlayCard 增加 InvalidTarget/TargetDead/UnsupportedTargetType 等结果；
         CanPlayCard 在命令出队时验证每个 Effect 所需目标。

验收：
  - Release 条件下非法 Effect 不会把 null Action 放入队列。
  - 人工抛错的 Action 不会让 IsRunning 永久为 true；战斗进入可诊断的 Faulted 状态。
  - 循环 Hook 在固定 Action 数处确定性终止。
  - 连续两场战斗不存在上一场队列、选择或故障状态。

3. 工作包 B：卡牌生命周期、消耗、弃牌与选择
------------------------------------------------------------------------

[ ] B-01 在 BattlePlayerState 增加 PlayPile；BattlePileApi 增加按 CardInstanceId 的原子
         MoveCard(from, to, cardId) 和带来源校验的语义封装。

[ ] B-02 新增 HandCardToPlayAction，成为出牌批次第一条状态修改：
         Hand -> Play。CostEnergy、卡牌 Effects、最终去向都在它之后。

[ ] B-03 改造 PlayedCardToDiscardAction：
         - 显式携带 PlayerId + CardInstanceId；
         - 从 PlayPile 移到 DiscardPile；
         - 若卡已被合法 Exhaust，返回 AlreadyMovedByTerminalEffect；
         - 其他缺失视为不变量错误，不能与合法消耗共用同一“skip”日志。

[ ] B-04 重做 ExhaustCardAction：
         - 删除 CardIndexArray；改为 PlayerId + CardInstanceId[]；
         - Exhaust Self 使用 SourceCardId，把当前打出的牌从 PlayPile 移到 ExhaustedPile；
         - 选中手牌消耗从 HandCards 移到 ExhaustedPile；
         - 每张牌产生明确结果并触发 Exhaust Hook；
         - 数量不足、重复 Id、卡不在允许来源牌堆都有确定规则。

[ ] B-05 重做 DiscardHandCardAction：
         - 增加构造函数并保证 Id/初始 ActionStatus 有效；
         - 显式携带 PlayerId + CardInstanceId[]；
         - 从 HandCards 移到 DiscardPile；
         - “指定弃牌”“随机弃牌”“回合结束弃手牌”使用不同的上层命令/Action 类型或
           明确的 Reason 枚举，以便 Hook 区分；
         - 随机弃牌只使用 BattleActionContext.RandomManager 的专用确定性域。

[ ] B-06 用命令化选择替换 HandCardChooseAction 的本地回调模型：
         - ChoiceRequest 包含 ChoiceId、ChoosingPlayer、候选 CardInstanceId 快照、
           Min/MaxCount、允许取消、Reason；
         - ActionExecutor.CurrentAction 暴露当前挂起请求；
         - 本地 UI 和远端网络统一提交 ChoiceCommand{ChoiceId, PlayerId, CardIds}；
         - BattleCommandApi 在稳定点例外通道中把匹配命令交给挂起 Action；
         - 校验选择者、ChoiceId、数量、候选集合和重复 Id；
         - 取消/主机超时产生确定结果，永不永久 WaitUntil；
         - 选择完成后由 Action 入队具体 Exhaust/Discard Action，或输出不可变选择结果。

[ ] B-07 将卡牌目标从实体 EnumTargetType 分离，至少支持：SelfCard、SelectedHandCard、
         RandomHandCard、AllHandCards。未实现类型不得进入运行时。

验收：
  - 出牌后效果执行期间该卡位于 PlayPile，不再占手牌容量。
  - 普通牌最终 Play -> Discard；Exhaust Self 最终 Play -> Exhaust，且不会再归弃。
  - 指定/随机/弃尽手牌均只移动预期 CardInstanceId，不受列表下标变化影响。
  - 选择可暂停、恢复、取消、由主机超时，并能通过命令日志重放。

[ ] D-04 把 AfterCardPlayed 的 Fire 从 BattleCommandApi 的队列构造期移动到真正的出牌

[ ] D-05 为 Damage/Draw/Discard/Exhaust/Status/Energy/Block 增加最小必要 HookType；每个
         Fire 点严格位于模拟 Action 内，反应继续翻译为普通 Action 尾插。

[ ] D-06 HookManager 收集顺序必须稳定。卡牌监听器不能直接依赖 Dictionary.Values 的

验收：
  - AllEnemy 对每个存活敌人各生成一次确定顺序的效果；RandomEnemy 在相同 seed/状态下

  - SelectedEnemy 不能选择玩家、死亡敌人或 default Id。
  - AfterCardPlayed 看到的是卡牌效果结算后的状态，且一次出牌只触发一次。
  - 任一 Action 日志都能从自身载荷说明“谁因哪张卡对谁做了什么”。

8. 总完成标准
------------------------------------------------------------------------

  - 10 个现有 GameAction 不再有日志占位或不可达死代码。
  - 所有 Action 的 Source/Target/Card/Value 语义明确，运行结果不依赖隐式当前玩家。
  - 所有 cards.json 可加载 Effect 都有真实实现；未支持组合在加载期明确失败。
  - 战斗可从出牌经过伤害/格挡/抽牌/状态/牌堆去向进入胜负，不永久挂起。
  - 本地、主机和远端输入统一走命令；选择可记录和重放。
  - 相同初始状态、seed、命令序列得到一致 Action 顺序与状态 hash。
  - Unity 编译 0 errors，Action 测试矩阵全部通过。
