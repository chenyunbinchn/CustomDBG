========================================================================
  缺陷记录：从尾部抽牌“顺序是反的”措辞含糊，造成困惑
  日期：2026-06-26
========================================================================

1. 出错的内容
------------------------------------------------------------------------
在讨论 BattlePileApi.Draw 从列表尾部抽牌时，我写道：
  “连续从尾抽，抽出的几张进 to 的顺序是原堆的逆序……如果你在意这批
   牌之间的相对顺序（比如做‘展示抽到的牌’动画），记住它是反的。”
用户随即追问“这里是什么意思”——说明“反的/逆序”指代不清，造成困惑。

2. 根因分析
------------------------------------------------------------------------
“逆序”没有写明【相对什么参照系】而言。实际上：
  - 相对“抽取先后 / 牌堆顶往下”：手牌(to)里是【正序】（先抽到的在前），
    对动画自然且正确，无需任何反转。
  - 仅相对“底层 List 的下标递增方向”才是“反的”，而该方向对玩家不可见、
    调用方一般也不应依赖。
我把一个对调用方无实际意义的内部存储方向，描述成像是需要处理的“坑”，
且未给出参照系。违反《Language & Response Quality》中“每句话自洽、
无未定义指代”的要求。

3. 修正
------------------------------------------------------------------------
澄清为：从尾抽时，手牌(to)中新抽的 count 张【按抽取先后排列】
（= 原抽牌堆从顶往下的顺序），动画直接顺序播放即可，无需反转。
用 [A,B,C,D,E] 抽 3 张 → to=[E,D,C] 的具体例子说明，并指出“List 存储
方向”是不可见的内部细节。

4. 教训
------------------------------------------------------------------------
说“顺序反了/逆序”时，必须显式写出参照系（相对抽取先后？相对列表下标？
相对显示顺序？），并说明它对调用方是否有实际影响。不要把对调用方不可见
的内部存储方向，当作需要注意的行为差异抛给对方。
