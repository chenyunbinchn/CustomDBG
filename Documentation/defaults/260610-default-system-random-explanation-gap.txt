1. 失误描述
------------------------------------------------------------------------

报告中存在两处导致误解的内容：

a) 第 3.1 节详细展示了线性同余法（LCG）的手动计算过程：

  原文：
    "一个极简的公式（线性同余法，LCG）：
     下一个数 = (当前数 * A + B) mod M
     假设 A=5, B=3, M=16，从'当前数=7'开始：
     第1次: (7 * 5 + 3) mod 16 = 38 mod 16 = 6 ..."

  这容易让读者以为需要自己实现这个公式来生成随机数。
  实际上 System.Random 已经内置了更好的算法，不需要自己写。
  3.1 节的目的是解释原理，不是要求实现，但报告没有明确说明这一点。

b) 第 3.3 节介绍 System.Random 时，只展示了用法，
   没有解释它的关键特征：

  - 没有说明 System.Random 是一个有状态的对象（实例），
    不是静态工具类
  - 没有说明它内部维护"当前走到哪一步"的状态
  - 没有说明这个实例必须被持久保存，否则状态丢失
  - 没有明确说"你不需要自己实现随机数生成算法"

  这导致读者在设计架构时，不清楚 System.Random 实例应该
  放在哪里、由谁管理，进而产生了关于 Rng 和 SeedManager
  职责划分的困惑。

------------------------------------------------------------------------

2. 根因分析
------------------------------------------------------------------------

a) 示例代码的目的未声明
   3.1 节展示 LCG 公式时，没有标注"这只是为了解释原理，
   实际项目中不需要自己实现"。读者无法区分"教学内容"
   和"实现要求"。

b) 省略了关键概念的核心特征
   介绍 System.Random 时，假设读者已理解"有状态对象"的含义。
   对于不熟悉 Random 的读者，"有状态"和"必须保持实例存活"
   是理解整个架构设计的前提，但报告跳过了这一步。

c) 违反了消歧义规则
   报告中同时出现了"手动公式"和"System.Random"两种方式，
   但没有明确说明两者的关系（后者替代前者），
   导致读者可能认为两者都需要实现。

------------------------------------------------------------------------

3. 修正措施
------------------------------------------------------------------------

更新报告 260610-report-random-system-fundamentals.txt：

a) 在 3.1 节末尾明确标注：
   "以上公式仅用于解释原理。实际项目中使用 C# 内置的
    System.Random，不需要自己实现随机数生成算法。"

b) 在 3.3 节增加对 System.Random 核心特征的解释：
   - 它是有状态的对象实例
   - 内部状态随每次 Next() 调用而改变
   - 实例必须被持久保存
   - 明确列出"需要自己实现"vs"不需要自己实现"的清单

------------------------------------------------------------------------

4. 经验总结
------------------------------------------------------------------------

在教学性报告中：
  - 展示原理性代码/公式时，必须明确标注"这是原理说明，
    不是实现要求"
  - 介绍一个外部工具/库时，不能只展示用法，
    必须说明它的核心特征（有状态 vs 无状态、实例 vs 静态等），
    因为这些特征直接影响架构设计
  - 当报告中出现多种实现方式时，必须明确说明它们的关系
    （替代、互补、还是选择其一）
