========================================================================
  DrawCardAction 现状报告
  日期：2026-09-01
========================================================================

------------------------------------------------------------------------
1. 结论
------------------------------------------------------------------------

DrawCardAction 尚未实现实际抽牌。

它已经能够由卡牌效果创建、进入 Action 队列并被 ActionExecutor 执行，但 Execute()
目前只输出一条日志并等待一帧，不会修改抽牌堆、手牌或弃牌堆。

因此 cards.json 中“剑柄打击”的 DrawCards=1 效果当前没有实际作用。

------------------------------------------------------------------------
2. 已经存在并可用的部分
------------------------------------------------------------------------

Effect 翻译：
  EffectApi 遇到 EnumEffectType.DrawCards 时，会创建 DrawCardAction。

Action 调度：
  BattleCommandApi 会按以下顺序加入 Action：
    扣除能量 -> 卡牌效果 -> 将打出的牌移入弃牌堆

  ActionExecutor 会依次执行这些 Action，并正确传入发起命令的 BattlePlayerState。

牌堆算法：
  BattlePileApi.DrawCards() 已经实现以下行为：
    - 从 DrawPile 尾部抽牌到 HandCards；
    - 抽牌堆为空时，把 DiscardPile 移入 DrawPile；
    - 使用 RandomManager 洗牌后继续抽取；
    - 两个牌堆都为空时提前结束；
    - 实际抽取数量可以少于请求数量。

测试入口：
  UnityBoostrap 的 S 键测试代码会直接调用 BattlePileApi.DrawCards(player, 3, rng)，
  所以通过 S 键可以正常改变抽牌堆和手牌。这条路径绕过了 DrawCardAction。

------------------------------------------------------------------------
3. 当前断点
------------------------------------------------------------------------

DrawCardAction.Execute() 当前只有：
  - 打印 Value；
  - yield return null。

它不能直接复用 BattlePileApi.DrawCards()，因为后者需要 RandomManager，而现有
GameAction.Execute() 只接收 BattleState 和 BattlePlayerState。

这说明问题不在牌堆算法，而在 Action 执行上下文缺少洗牌所需的确定性随机源。

------------------------------------------------------------------------
4. 对当前游戏流程的影响
------------------------------------------------------------------------

  - EnterBattle() 只构建并洗牌 DrawPile，没有抽取初始手牌。
  - 不使用 S 键测试入口时，战斗开始后的 HandCards 为空。
  - 即使通过 S 键拿到并打出“剑柄打击”，它也只造成伤害，不会抽一张牌。
  - UI 可以正确显示当前 HandCards、DrawPile 和 DiscardPile，但不会自行执行抽牌。
  - 当前没有手牌上限规则，也没有抽牌动画或抽牌结果事件。

------------------------------------------------------------------------
5. 实现时需要决定的事项
------------------------------------------------------------------------

推荐先扩展 Action 执行上下文，让 DrawCardAction 能获得同一局战斗的 RandomManager，
然后在 Execute() 中调用 BattlePileApi.DrawCards(playerState, Value, randomManager)。

可以采用项目现有 TODO 中提到的 BattleContext，统一携带 BattleState、当前玩家状态和
RandomManager。这样不会让 UI 或 DrawCardAction 自己创建随机源，也能维持确定性执行。

随后还需要：
  1. 决定初始手牌由 EnterBattle、回合开始 Action，还是独立 BattleCommand 触发；
  2. 明确手牌上限以及满手时卡牌的去向；
  3. 为普通抽牌、空堆重洗、数量不足和多玩家归属添加测试；
  4. 最后增加 UI 展示事件和动画，但不让 UI 修改牌堆状态。

------------------------------------------------------------------------
6. 测试覆盖
------------------------------------------------------------------------

当前未找到针对 BattlePileApi.DrawCards 或 DrawCardAction 的自动化测试。
