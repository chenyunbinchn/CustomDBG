========================================================================
  规则：最小 UI 框架
========================================================================

修订记录：
  2026-08-25 初版：确定 UI 分类、生命周期和读写分离。
  2026-09-01 精简：只保留第一阶段投入使用必须遵守的规则。
  2026-09-02 命名：根 UI 名称必须以所属 UI 类型结尾。

------------------------------------------------------------------------
1. UI 职责
------------------------------------------------------------------------

  - View 只显示 ViewModel、采集输入和播放表现动画。
  - UI 不得修改 Hp、能量、牌堆、卡牌位置等业务状态。
  - 战斗逻辑不得引用 ui 命名空间。
  - UIManager 不得读取 BattleState、CardInstance 或其他业务对象。

------------------------------------------------------------------------
2. 四类根 UI
------------------------------------------------------------------------

  - Page：全屏页面；同一时间最多一个。
  - HUD：依附当前 Page；Page 关闭时一并关闭。
  - Modal：按栈覆盖；只有栈顶可以交互。
  - Overlay：位于最上层；不进入 Modal 栈。

UIManager 只管理这四类根 UI。
CardView、血条和列表元素由所属 Page/HUD 创建、复用和释放。

根 UI 命名必须使用“功能名 + UI 类型”：
  - Page：BattlePage、HomePage；
  - HUD：BattleHUD；
  - Modal：CardPileDialogModal、SettingsDialogModal；
  - Overlay：LoadingOverlay。

内部组件不添加根 UI 类型后缀，例如 CardView、HandView、CardPileListView。

------------------------------------------------------------------------
3. 读写分离
------------------------------------------------------------------------

读：
  Domain State -> Presenter/Mapper -> immutable ViewModel -> View.Render

写：
  用户输入 -> Intent -> Presenter/Controller -> Command/业务入口

ViewModel：
  - 可以包含显示文本、Sprite、显示状态和稳定 Id。
  - 不得包含可变业务对象、业务修改函数或点击业务委托。

Intent：
  - 只表示用户想做什么，不表示业务已经成功。
  - 战斗输入最终必须进入 BattleCommandApi。

------------------------------------------------------------------------
4. 根 UI 生命周期
------------------------------------------------------------------------

打开：
  1. Addressables 加载根 Prefab；
  2. 放入固定 Layer；
  3. 禁止输入；
  4. Render ViewModel；
  5. 等待打开动画；
  6. 开放输入。

关闭：
  1. 禁止输入；
  2. 等待关闭动画；
  3. 解绑 ViewModel 和事件；
  4. 销毁实例并释放 Addressables 句柄。

第一阶段所有根 UI 关闭后都释放，不实现缓存。
第一阶段同时只执行一个根 UI 操作。

------------------------------------------------------------------------
5. 固定层级
------------------------------------------------------------------------

  PageLayer     sortingOrder = 0
  HudLayer      sortingOrder = 1000
  ModalLayer    sortingOrder = 2000
  OverlayLayer  sortingOrder = 3000

具体 View 不得修改这些根层级的 sortingOrder。

------------------------------------------------------------------------
6. 第一阶段明确不做
------------------------------------------------------------------------

  - 不做 UICatalog 和 UIKey 封装，直接使用 Addressables 地址。
  - 不做 CacheOnClose。
  - 不做 OwnerScope 类型；HUD 和 Modal 默认属于当前 Page。
  - 不做 UIState 枚举。
  - 不做统一 Intent 标记接口。
  - 不做自动绑定、反射绑定或响应式框架。
  - 不做并行转场、请求排队和转场取消。

只有出现第二个真实需求或性能数据后，才增加对应抽象。

------------------------------------------------------------------------
7. 最小验收
------------------------------------------------------------------------

  [ ] HomePage 可以打开。
  [ ] 打开 BattlePage 会关闭 HomePage。
  [ ] BattlePage 关闭时会清理 BattleHUD。
  [ ] SettingsDialogModal 可以压入 ConfirmDialogModal，Pop 后恢复下层输入。
  [ ] Overlay 显示在 Modal 上方。
  [ ] View 只接收 IUIViewModel。
  [ ] CardView 输出 Intent，不直接调用 BattleCommandApi。
  [ ] 每次加载都有对应 Addressables 释放。
