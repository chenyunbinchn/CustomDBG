------------------------------------------------------------------------
1. 联机拓扑（listen server）
------------------------------------------------------------------------
  1-1. 一名玩家为主机：主机进程 = 权威模拟 + 自己的本地客户端；
       其余玩家为纯客户端；无专用服务器。
  1-2. 主机自己的输入与远端玩家的输入走同一命令入口。禁止任何
       "因为权威状态就在本进程里"而直接修改它的主机特权路径。

------------------------------------------------------------------------
2. 输入命令化（BattleCommand）
------------------------------------------------------------------------
  2-1. 一切战斗输入（出牌、将来的结束回合/选牌等）必须表达为纯值
       类型的命令 struct（字段只允许 enum / 值类型 Id / int）。
       命令即网络消息本身，也是回放记录的一行。
  2-2. 命令用 Id 指代实体（ActionEntityId / CardInstanceId），禁止
       对象引用，禁止手牌下标（下标是 UI 层概念）。
  2-3. 本地 UI 与远端网络消息汇合到同一提交点
       （BattleCommandApi.Submit），之后路径完全相同。

------------------------------------------------------------------------
3. 串行结算（稳定点规则）
------------------------------------------------------------------------
  3-1. 命令是原子事务：一条命令展开的全部 GameAction（含执行过程中
       新产生的）结算完毕、action 队列彻底为空（稳定点）之后，才
       执行下一条命令。
  3-2. 稳定点的判定条件是"action 队列干涸"，不是入队那一刻的条数
       （hook 反应等会让条数动态增长）。
  3-3. 结算期间其他玩家的命令排队等待，绝不丢弃：串行点在命令队列
       的【出口】，不在入口。禁止以"executor 正忙"为由拒绝输入；
       只有规则性非法（回合/能量/卡不在手）允许失败。
  3-4. 权威校验在命令出队、即将执行时做（不在提交时）：前序命令的
       结算可能改变本命令的合法性。校验失败 = 丢弃；各端状态一致，
       丢弃结果自然一致，无需协商。
  3-5. 例外：等待玩家选择的 action 挂起队列时，该玩家的"选择命令"
       是喂给挂起 action 的输入、直接被消费，不受稳定点约束；其余
       命令继续排队。联机下选择必须有超时（防掉线卡死全场）。
  3-6. 同时行动 = 任意顺序的串行：主机按命令到达先后定序，规则上
       不存在"同一瞬间"，一切效果严格先后结算。

------------------------------------------------------------------------
4. 队列与 action 化
------------------------------------------------------------------------
  4-1. 全场唯一一条共享 ActionQueue：action 的全局顺序 = 战斗的事实
       顺序，回放与网络同步都以它为准。
  4-2. 改变战斗状态的原子操作（扣能量、移牌、扣血、加格挡…）一律
       action 化入队执行；禁止在命令执行函数里直接修改状态集合
       （校验的只读访问除外）。
  4-3. 每种牌堆移动是独立的 action 类型："打出后归弃"与"弃牌"是
       两种语义、两个 action（将来触发的 hook 不同）。

------------------------------------------------------------------------
5. 玩家标识
------------------------------------------------------------------------
  5-1. 玩家编号统一用 ActionEntityId(EnumEntityType.Player, index)，
       index == BattleState.Players 数组下标（StateManager.Init 赋值）。
       不设独立的玩家枚举（EnumPlayerIndex 已删除）。

------------------------------------------------------------------------
6. 随机与种子
------------------------------------------------------------------------
  6-1. 随机域全局共享（全体玩家共用每域一条流），正确性由"全端以
       同一顺序执行命令"保证（见第 3 节）。
  6-2. MainSeed 由主机生成、随对局初始化消息分发给客户端；客户端
       禁止自行生成种子。
